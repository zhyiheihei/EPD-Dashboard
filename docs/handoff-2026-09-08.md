## 四、操作手册要点（血泪教训浓缩）

- **bleak 必须 <1**（现 0.22.3）：装 mcp 时 uv 曾把它拉到 3.0.2 导致 BLE 全挂，且 BlueZ 会缓存损坏状态需 `bluetoothctl remove F7:F3:13:0B:3E:1C` 重连。生产用 nix 管理依赖无此问题
- **opi5p 蓝牙 rfkill 软屏蔽**：部署后若"No Bluetooth adapters found"，`rfkill unblock bluetooth`（当前状态：unblocked ✓，但重启后可能复发——固化进 nixos 配置这件事还没做）
- **固件 OTA 流程**：改 `EPD_service.h` 的 APP_VERSION → `make -f Makefile.firmware clean && make -f Makefile.firmware ota`（nix develop 内）→ 服务端 API 上传 `/api/ota/firmware` → `POST /api/ota/push {"firmware_id": N}` → 验证 `/api/ota/device?refresh=1` 版本号。OTA 后设备停在 bootloader（DfuTarg，MAC 末位+1）约 60s
- **WebUI 磁盘缓存**：Chrome headless 测试用独立 user-data-dir；服务端 static 已发 no-cache 头
- **pkill 自杀**：`pkill -f "epd_food_server"` 会匹配自己的命令行，用 `[e]pd_food_server` 模式
- **同一时刻只允许一个 BLE 扫描进程**（手动测试扫描会撞服务端推送）
- 设备 MAC：F7:F3:13:0B:3E:1C（bootloader 为 ...3E:1D）；当前固件 v27；CAPS 报食品上限 4、单包 244B
- MCP 接入配置（pi 客户端）：command=`/home/zhyi/Documents/repositories/EPD-Dashboard/.venv/bin/python`，args=`["-m","epd_dashboard_mcp"]`，cwd=`.../EPD-Dashboard/server`，env `EPD_MCP_BASE_URL=http://127.0.0.1:13836`（生产）
